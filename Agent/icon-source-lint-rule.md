# Add the `expo-ui/icon-source` lint rule: ban Lucide and vector-icon imports, autofix alias icon names

## Goal

Add a sixth rule, `expo-ui/icon-source`, to `@mrmeg/eslint-plugin-expo-ui` (`packages/lint`). It does two things:

1. It reports every import of an icon library: Lucide's React packages and the vector-icon fonts. The message names the replacement, which is `<Icon name="<canonical>" />` plus the command that registers the name.
2. It autofixes Lucide alias names to their canonical names in `name="…"` / `icon="…"` JSX attributes on design-system components. An alias is an old, renamed Lucide name, such as `home` → `house`.

Since expo-ui 0.29.0, `Icon` draws glyph data that the app registers, and no icon library is a peer. Consumer apps are dropping `lucide-react-native` and `@expo/vector-icons`, and this rule keeps those imports from coming back. `packages/ui/src/components/iconTypes.ts` already promises this rule as "a follow-up".

## Context

Verified on `dev` @ 925429a.

**Plugin layout.**
- `packages/lint/rules/` has five rules: no-arbitrary-values, no-raw-colors, no-raw-primitives, no-raw-typography, no-restyle.
- `index.js` registers all five and enables them at `error` in `plugin.configs.recommended`.
- None of the rules is `fixable`. This will be the plugin's first autofix.
- Rules load facts with `readSettings(context)` (`lib/settings.js`) and `loadDesignSystemFor(settings)` (`lib/source.js`).
- `settings.origin.kind` is one of:
  - `"source"`: this repo, reading `packages/ui/src`.
  - `"manifest"`: a consumer, reading `@mrmeg/expo-ui/design-system.json`.
  - `"none"`.
- Each rule's `Program` visitor is `reportMissingDesignSystem(...)`.
- `lib/components.js` `designSystemComponent(openingElement, context, settings)` resolves a JSX element to its imported design-system name. It returns an object `{ name, root, source }` (use `.name`: `Icon`, `Button.Icon`, `ToggleIcon`, `Item`, …), and returns `null` for local components.
- The `import`/specifier handling to copy is in `rules/no-raw-primitives.js`.

**The loaders read no icon names or aliases today.** The only icon facts in `lib/source.js` and `lib/manifest.js` are the `icon*` size tokens.
- Sources (this repo):
  - `packages/ui/src/components/icon-names.json` is a sorted array of the 19 builtin names (`check`, `chevron-down`, …).
  - `packages/ui/src/icons/lucide.json` (446 KB) is `{ lucide: "1.55.0", aliases: { "home": "house", "alert-circle": "circle-alert", … 260 }, icons: { …1877 glyphs } }`. It is generated by `bun run ui:icons` (`scripts/build-icon-registry.mjs`) and must never be hand-edited.
- Manifest: `scripts/build-design-system-manifest.mjs:93` writes `icons: { names: iconNames, aliases: lucideSnapshot.aliases, lucide: lucideSnapshot.lucide }` into `dist/design-system.json`, after the `...serializeDesignSystem(...)` spread. `schemaVersion` stays 2. The key is additive, and the loader ignores keys it does not read.
- **Shipped expo-ui 0.28.0 already has an `icons` block, but it is `{ names }` only**: 145 names, with no `aliases` and no `lucide` (`git show expo-ui-v0.28.0:scripts/build-design-system-manifest.mjs`). Manifests from 0.27 and earlier have no `icons` key. Only 0.29.0 has `aliases`. 0.29.0 is open on dev and unpublished; npm has 0.28.0.

**Icon props.**
- In `packages/ui/src/components/Icon.tsx`, `IconName` is the builtins plus the names the app registers. An unregistered literal, including an alias, is a type error.
- `Icon`, `Button.Icon` (also exported as `ButtonIcon`), `ToggleIcon`, and `ToggleGroupIcon` take `name`. These are exactly the design-system components whose resolved name ends in `Icon` (the source loader knows `Button.Icon`, `ButtonIcon`, `Icon`, `ToggleIcon`, `ToggleGroupIcon`). `ToggleIcon` and `ToggleGroupIcon` are flat exports, not `Toggle.Icon`, so a check for `Icon` or `*.Icon` alone would miss them.
- No other `IconName`-typed prop exists besides `name` and `icon`.
- `Tabs`, `StatCard`, `Item`, `Avatar`, and `EmptyState` take `icon?: IconName`.

**CLI.** `packages/ui/bin/expo-ui-icons.mjs` handles aliases:
- `add home` adds `house` instead.
- `generate` rejects alias names.
- `init` scans `name=`/`icon=` literals and lists the alias hits it skips.

Consumers run it as `bunx expo-ui-icons …`, which is how `packages/ui/README.md`, `packages/ui/LLM_USAGE.md`, and `docs/migration-guide.md` all document it. **This repo has no `node_modules/.bin/expo-ui-icons`**, so `bunx expo-ui-icons` here would go to the npm registry. Here the command is `bun run icons add <name>` (root script, documented in `AGENTS.md`).

**Quirk (vault).** `lucide-react-native/icons/<alias>` (e.g. `home`, `alert-circle`) type-checks but has no runtime file, so Metro fails. Canonical names only.

**Banned-import precedent.** `scripts/check-ui-forbidden-imports.mjs` scans only `packages/ui/src` and `dist` for `lucide-react-native`, `lucide-react`, `@expo/vector-icons`, and the reanimated/worklets packages. It never scans app code.

**Name resolution, checked against all 2137 Lucide 1.55 names (canonical plus alias).** Resolution works like this:
1. Strip a `Lucide` prefix and an `Icon` suffix.
2. Convert to kebab case with `p.replace(/(?<!^)([A-Z])/g, "-$1").replace(/(?<![0-9])([a-zA-Z])([0-9])/g, "$1-$2").toLowerCase()`.
3. Map through `aliases`.

This yields the correct canonical name for every one of them. Examples:

| Import | Canonical name |
|---|---|
| `Home` / `HomeIcon` / `LucideHome` | `house` |
| `AlertCircle` | `circle-alert` |
| `XCircle` | `circle-x` |
| `BarChart2` | `chart-no-axes-column` |
| `Grid2x2` | `grid-2x2` |
| `CalendarX2` | `calendar-x-2` |
| `ArrowDown01` | `arrow-down-0-1` |
| `Archive` | `archive` |

No snapshot name ends in `-icon` or starts with `lucide`.

**This rule lands green.**
- `git grep -E "lucide-react|@expo/vector-icons|react-native-vector-icons"` over ts/tsx/js/mjs/cjs/json matches only `scripts/check-ui-forbidden-imports.mjs`.
- No `name=`/`icon=` literal in `app/`, `client/`, or `shared/` is an alias.
- `bun lint:ui` → `✓ no design-system violations (343 files)`.
- `bun run lint:test` → 11 suites, 196 tests pass.
- `bun lint:ui --doctor` → all `ok`, with `smoke fixture: … = 1/1/3/2/1 (expected 1/1/3/2/1)`.

**Constraints.**
- `eslint.config.mjs` applies `configs.recommended` to `app/`, `client/`, and `shared/` only, not to tests. `lucide-static`, a root devDependency read by `scripts/`, is outside that scope and must not be banned.
- No version bump is needed: `dependencies`, `peerDependencies`, `exports`, and `files` don't change.
- `packages/lint/README.md` is an llms-full source, so `llms-full.txt` must be regenerated (`bun run docs:llms`) or `bun run gen --check` fails.
- Never hand-edit generated files.
- `expo lint` caches messages in `.expo/cache/eslint/`, so use `--no-cache` after rule changes.
- The checkout may carry another thread's uncommitted dependency bumps. Never reset or stash them wholesale, and never `bun install` over them.

### 2. `packages/lint/rules/icon-source.js` (new)

**Meta:** `meta.type: "problem"`, `fixable: "code"`, `schema: []`. Messages are `{ iconComponent, iconLibrary, iconFont, aliasName }`, each `"{{message}}"`, plus `...DESIGN_SYSTEM_MISSING_MESSAGES`. The `docs.description` is shown by `--rules`: "Draw icons with `Icon` and registered Lucide names: no Lucide or vector-icon imports, and Lucide's old (alias) names rewritten to their canonical names."

**`create`:**
- Call `readSettings`, then `loadDesignSystemFor`.
- `Program: reportMissingDesignSystem(...)`. The import ban still runs when no design system loads.
- `register(n)` is the clause that tells the user how to register name `n`. It is a three-way choice. The `expo-ui-icons` bin, `IconComponent`, and `registerIcons` first ship in 0.29.0, so a bare `bunx expo-ui-icons` on 0.28 or with nothing installed would resolve an unvetted npm package.
  - When `design.icons.lucide` is null (0.28 or older manifest, no design system, sources without a snapshot): `` upgrade `@mrmeg/expo-ui` to 0.29.0 or later, then run `bunx expo-ui-icons add <n>` ``.
  - Else, when `settings.origin.kind === "source"` (this repo and template forks): `` run `bun run icons add <n>` ``.
  - Else (a 0.29+ manifest): `` run `bunx expo-ui-icons add <n>` ``.
  - All three forms must be pinned in tests.
- The rule owns its banned list. A published plugin cannot import `scripts/`, and that script also bans reanimated:
  - Lucide: `lucide-react-native`, `lucide-react`, and any subpath of either.
  - Fonts: `@expo/vector-icons` and subpaths, `react-native-vector-icons` and subpaths, `@react-native-vector-icons/*`.
- Check these nodes, matching the exact name or `name/…`:
  - `ImportDeclaration`
  - `ExportNamedDeclaration` / `ExportAllDeclaration` with a `source`
  - `ImportExpression` with a string-literal source
  - `require("…")` with a string-literal first argument
- **Type-only imports are reported too.** This is deliberately unlike `no-raw-primitives`: the goal is to remove the package from `package.json`, and a type import still needs it.

**Lucide `ImportDeclaration`:**
- Each `ImportSpecifier` whose imported name starts with an uppercase letter and is not in `{Icon, LucideIcon, LucideProps, IconNode, LucideProvider, DynamicIcon}` gets an `iconComponent` report on the specifier, with the canonical name resolved as in Context:
  1. Strip `^Lucide(?=[A-Z0-9])` and `(?<=.)Icon$`.
  2. Apply the kebab regexes.
  3. Look the result up in `design.icons.aliases`. With no aliases, the kebab name is used as-is.
- If the declaration has no icon specifier, or has any other specifier (default, namespace, lowercase such as `icons` / `createLucideIcon`, or one of the listed non-icon names), report `iconLibrary` once on `node.source`.
- A subpath whose last segment follows an `icons` segment and, minus `.js`/`.mjs`, is kebab-case (`lucide-react-native/icons/home`) gets `iconComponent` on `node.source`, using that segment as the kebab name.
- Everything else from Lucide gets `iconLibrary` on the source or literal.

**Vector-icon sources:** report `iconFont` once on the source or literal.

**Alias autofix**, only when `design.icons.aliases` has entries:
- On `JSXAttribute`, resolve `node.parent` (the `JSXOpeningElement`) with `designSystemComponent` and read `.name` from the result.
- Check an attribute named `name` when that name ends in `Icon` (`/Icon$/`: `Icon`, `Button.Icon`, `ButtonIcon`, `ToggleIcon`, `ToggleGroupIcon`). Check an attribute named `icon` on any design-system component.
- Walk the value: a string `Literal`; an expression container holding a `Literal`; a `TemplateLiteral` with no expressions; `ConditionalExpression` consequent/alternate; `LogicalExpression` left/right.
- For each string that is a key of `aliases`, report `aliasName` on that node. The fix replaces the node, keeping its quote character (or backticks), with the canonical name.

**Message texts.** `{{register:x}}` is the `register(x)` clause above, where `x` is the canonical name or the literal `<name>`. Each line below is one message, written literally, and tests pin these strings.

- `{{name}}` is the imported name (`AlertCircle` for `AlertCircle as Alert`), or the subpath segment.
- `{{source}}` is the import source as written.
- `{{aliasNote}}` is `` (`<kebab>` is Lucide's old name for `<canonical>`)`` when the kebab name was an alias, and empty otherwise.

```
iconComponent: `{{name}}` from `"{{source}}"` is an icon-library component. Use `<Icon name="{{canonical}}" />` from `"@mrmeg/expo-ui/components"`{{aliasNote}}; if `{{canonical}}` is not registered yet, {{register:canonical}}.
iconLibrary:   `"{{source}}"` is an icon library; `Icon` from `"@mrmeg/expo-ui/components"` draws Lucide glyphs without one. Use `<Icon name="…" />` with a kebab-case Lucide name (to register one, {{register:<name>}}), type icon props with `IconName` or `IconComponent` from `"@mrmeg/expo-ui/components/Icon"`, and pass `component` for art that is not a Lucide icon.
iconFont:      `"{{source}}"` is an icon font outside the design system. Use `<Icon name="…" />` from `"@mrmeg/expo-ui/components"` with a kebab-case Lucide name (to register one, {{register:<name>}}), list native tab bar glyphs under `tabIcons` in `client/icons.json`, and pass `component` for art that is not a Lucide icon.
aliasName:     `"{{alias}}"` is Lucide's old name for `"{{canonical}}"`, and `Icon` registers canonical names only. Use `{{prop}}="{{canonical}}"`; if it is not registered yet, {{register:canonical}}.
```

For example, in this repo `import { Home } from "lucide-react-native"` reads:

```
`Home` from `"lucide-react-native"` is an icon-library component. Use `<Icon name="house" />` from `"@mrmeg/expo-ui/components"` (`home` is Lucide's old name for `house`); if `house` is not registered yet, run `bun run icons add house`.
```

Against a 0.28 manifest, the same import reads:

```
… Use `<Icon name="home" />` from `"@mrmeg/expo-ui/components"`; if `home` is not registered yet, upgrade `@mrmeg/expo-ui` to 0.29.0 or later, then run `bunx expo-ui-icons add home`.
```

Build each message in JS and pass it through the `{{message}}` placeholder, as the other rules do.

## Exclusions

- No `--fix` flag for `bun lint:ui`. Fixes apply through `eslint --fix`, `bun run lint --fix`, or the editor.
- No autofix of imports, which would need call-site rewrites.
- No alias fixes in object literals (`{ icon: "home" }`) or in non-design-system JSX. Typecheck and `expo-ui-icons init` already flag those.
- No change to `scripts/check-ui-forbidden-imports.mjs`, `serializeDesignSystem`, the manifest `schemaVersion`, the doctor's `errorCount >= 4` threshold, or any package version.
- No consumer-app changes. The 0.29 consumer bumps are a separate spec.
