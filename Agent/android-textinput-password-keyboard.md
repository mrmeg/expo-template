# Android `TextInput`: secure fields declare a password keyboard

## Goal

On Android, a package `TextInput` with `secureTextEntry` reports a password input type to the IME (`adb shell dumpsys input_method` shows a `textPassword` variation, Gboard shows no suggestion strip, nothing is learned), in both the masked and the revealed (eye toggle) state, without changing the field's look, focus, text or selection behavior that 0.25.1 established. This unblocks `~/Development/doglog/Agent/android-password-fields-input-type.md`.

## Context

Verified on `dev` at `abd3380` (package 0.25.1, `@expo/ui` 58.0.2 installed; doglog runs 57.0.14, tractor-tools-direct 57.0.4; the package peer range is `>=56 <59`).

- **Root cause is in `@expo/ui`'s universal Android field, identical in 56.0.21, 57.0.14 and 58.0.2** (`node_modules/@expo/ui/src/universal/TextInput/index.android.tsx`): `secureTextEntry` only sets `visualTransformation="password"` (line 182). `keyboardOptions.keyboardType` comes from `mapKeyboardType(keyboardType ?? inputModeToKeyboardType(inputMode))` (lines 29–58, 99, 136–143), and no RN `KeyboardTypeOptions` value maps to Compose's `'password'` or `'numberPassword'` (`'visible-password'` maps to `'text'`). The component spreads nothing else through, so there is no injection point. The Kotlin side does support it: `android/src/main/java/expo/modules/ui/textfield/TextFieldShared.kt` lines 83–93 map `"password"` → `KeyboardType.Password` and `"numberPassword"` → `KeyboardType.NumberPassword`; `TextFieldKeyboardOptionsRecord` also carries `autoCorrectEnabled`, `capitalization`, `imeAction`.
- **The building blocks are public and stable.** `@expo/ui/jetpack-compose` exports `BasicTextField` (with `.DecorationBox`, `.Placeholder`, `.InnerTextField` slots), `Box`, `Text`, `useNativeState`, and the types `TextFieldRef`, `TextFieldKeyboardType`, `TextFieldImeAction`, `TextFieldKeyboardOptions`; `@expo/ui/jetpack-compose/modifiers` exports `fillMaxWidth`, `onSizeChanged`, `semantics`, `testID`, `padding`, `paddingAll`. `BasicTextField.tsx` and `TextField/shared.ts`'s public types are byte-identical between 57.0.14 and 58.0.2 and differ from 56.0.21 only in an internal `useHostedTextInput` hook (npm tarball diffed). The universal wrapper's only non-public import is `transformToModifiers` from `../transformStyle` (`transformStyle.android.ts`), which the package does not need in full: `TextInput.tsx` line 794 hands the native field a `boxStyle` of exactly `{ backgroundColor: "transparent", paddingHorizontal, paddingVertical }` — the surface (fill, border, radius) is painted by the RN wrapper `View` (`surfaceStyle`, line 773).
- **Package call site.** `TextInput.tsx` lines 24–29 import `Host`, `TextInput as ExpoTextInput`, `useNativeState`, `TextInputRef` from `@expo/ui`; line 488 `type ExpoTextInputProps = ComponentProps<typeof ExpoTextInput>`; lines 855–902 render one `Host` per active flavour with `<ExpoTextInput {...rest} autoFocus value={state} defaultValue onChangeText onFocus onBlur editable multiline rows inputMode secureTextEntry placeholderTextColor style={boxStyle} textStyle={textStyle} ref=…/>`. Android keeps one mounted `Host`/field (`key="android"`) and flips `secureTextEntry` in place (the 0.25.1 fix); `TextInput.android.test.tsx` locks that identity with a lifecycle-recording `@expo/ui` mock (`compose-host`, `compose-input` testIDs). The platform-file pattern already exists (`keyboardController.ts` + `keyboardController.native.ts`); `tsconfig.build.json` compiles every `src/**/*.tsx`, so `.android.tsx` lands in `dist` and Metro picks it on Android while TypeScript types the import from the default file.
- **Compose semantics.** `KeyboardType.Password` with `VisualTransformation.None` is the canonical revealed-password state: the IME still sees a password field (no suggestions, no learning) while the text is visible. Keeping `keyboardType` constant across the eye toggle also avoids an IME restart, so focus and selection survive exactly as 0.25.1 requires.
- **Jest.** `jest-expo` resolves the iOS platform files, so `TextInput.android.test.tsx` (which flips `Platform.OS` at runtime) keeps hitting the default file and its existing `@expo/ui` mock. `test/setup.ts` mocks `@expo/ui` (root) only; nothing mocks `@expo/ui/jetpack-compose`.

## Work

1. **Platform module.** Add `packages/ui/src/components/nativeTextField.tsx` that re-exports `TextInput as NativeTextField` and `type TextInputProps as NativeTextFieldProps` from `@expo/ui` (iOS and Jest keep the universal field), and `packages/ui/src/components/nativeTextField.android.tsx` exporting the same two names with a package-owned field. The Android file is a port of `@expo/ui`'s `universal/TextInput/index.android.tsx` (MIT; say so in the header comment and name the version ported) built on `BasicTextField`: same prop surface (`NativeTextFieldProps = TextInputProps` from `@expo/ui`), same `useNativeState` fallback buffer, same `ref` handle (`focus`, `blur`, `clear`, `isFocused`, `setSelection`), `onFocusChanged` → `onFocus`/`onBlur`, `onSubmitEditing` wired to every IME action, `placeholder` via `BasicTextField.Placeholder` inside a `fillMaxWidth()` `Box`, `textStyle`/`textAlign`, `cursorColor`/`caretHidden`, `textSelectionColors`, `maxLength`, `selection`/`onSelectionChange`, `selectTextOnFocus`, `singleLine`/`maxLines`/`minLines` from `multiline`/`numberOfLines`/`rows`, `readOnly`/`editable`. Replace `transformToModifiers(style, {})` with a local mapping of the style keys the package sends — `padding`, `paddingVertical`, `paddingHorizontal`, `paddingTop/Bottom/Left/Right` → `paddingAll` or `padding(start, top, end, bottom)` — plus `testID`, `autoComplete` → `semantics({ contentType })`, `onContentSizeChange` → `onSizeChanged`, and `modifiers` passthrough, in the same order the original uses. Ignore `backgroundColor` (the RN surface paints it).
2. **Keyboard options.** In the Android file compute `keyboardOptions` as the original does, then when `secureTextEntry` is true: `keyboardType` is `'numberPassword'` if the mapped type is `'number'`, `'decimal'` or `'phone'`, otherwise `'password'`; `autoCorrectEnabled` defaults to `false` (an explicit `autoCorrect` prop still wins); `capitalization` defaults to `'none'`. `visualTransformation` stays `secureTextEntry ? "password" : undefined`. Do not default `autoComplete`; consumers pass `autoComplete="password"` / `"new-password"` for autofill hints.
3. **Call site.** `TextInput.tsx`: import `NativeTextField`/`NativeTextFieldProps` from `./nativeTextField` and render it where `ExpoTextInput` is rendered; `ExpoTextInputProps` becomes `NativeTextFieldProps`; keep `Host`, `useNativeState`, `TextInputRef` from `@expo/ui`. Masked and revealed states both keep `secureTextEntry` semantics as today (`secureTextEntry={secure}`), the Android file turns that into the constant password keyboard plus the toggled transformation. Update the `NativeTextInput` doc comment to say the Android field is package-owned and why.
4. **Tests.**
   - New `packages/ui/src/components/__tests__/nativeTextField.android.test.tsx` importing `../nativeTextField.android` directly, with `jest.mock("@expo/ui/jetpack-compose", …)` (a recording `BasicTextField` that exposes its props and a ref with `focus/blur/clear/setSelection` mocks, plus passthrough `Box`, `Text`, `useNativeState`) and `jest.mock("@expo/ui/jetpack-compose/modifiers", …)` (each modifier returns a tagged object). Assert: `secureTextEntry` → `keyboardOptions.keyboardType === "password"`, `autoCorrectEnabled === false`, `capitalization === "none"`, `visualTransformation === "password"`; `secureTextEntry={false}` on the same rendered element (revealed) keeps `keyboardType === "password"` and drops `visualTransformation`; `secureTextEntry` + `keyboardType="number-pad"` → `"numberPassword"`; `autoCorrect` explicitly `true` survives; a plain field with no keyboard props passes `keyboardOptions` `undefined` and a plain field with `keyboardType="email-address"` gets `"email"` (parity with the universal wrapper); `style={{ paddingHorizontal: 12, paddingVertical: 8 }}` produces the `padding(12, 8, 12, 8)` modifier and `testID` produces the testID modifier; `onFocusChanged(true/false)` calls `onFocus`/`onBlur`; the ref handle delegates `focus`, `blur`, `clear`, `setSelection` and `isFocused` tracks focus; `onSubmitEditing` is attached to `onDone`, `onGo`, `onNext`, `onSearch`, `onSend`, `onPrevious`.
   - `TextInput.android.test.tsx` and `TextInput.test.tsx` keep passing unchanged (the default file still maps to the existing `@expo/ui` mock).
   - `nativeTextField.tsx` (default) is covered by an assertion that it re-exports `@expo/ui`'s `TextInput` (same reference).
5. **Gates and docs.** `bun run ui:typecheck` (both platform files compile), `bun run ui:build` then `ls packages/ui/dist/components/nativeTextField*.js` shows both files, `bun run ui:consumer-smoke`. `packages/ui/README.md`: in the `TextInput` row or the native-input notes, one sentence that Android secure fields use a password keyboard (masked and revealed) and that the Android field is package-owned on top of `@expo/ui/jetpack-compose`'s `BasicTextField`. `CHANGELOG.md` under `## [Unreleased]` → `### Fixed`: Android secure fields declare a password keyboard type (`textPassword`, or `numberPassword` for numeric keyboards), autocorrect off by default, revealed text keeps the password keyboard. Run `bun run docs:llms` and commit regenerated files if changed. Sibling PRs (`icon-lucide`, `bottom-sheet-native-body-and-tap-away`) also append to Unreleased — rebase and keep all entries.

## Validation

- `bun run ui:test`, `bun run verify` green with fresh output; `bun run ui:consumer-smoke` passes (packed tarball still resolves and type-checks; the new file imports only `@expo/ui/jetpack-compose` and `@expo/ui/jetpack-compose/modifiers`, both in the peer's export map since 56).
- `grep -rn "from \"@expo/ui\"" packages/ui/src/components/TextInput.tsx` still shows `Host`, `useNativeState`, `TextInputRef` only.
- Optional device pass (emulator `emulator-5554` API 36 or Pixel 6a `2A271JEGR01748`; the 2026-09-17 debug APK plus Metro suffices, no native rebuild): open the sign-in block or `form-demo`, focus the password field, `adb shell dumpsys input_method | grep inputType` shows `0x81` or `0xe1` (or `0x12` for a numeric secure field) masked and revealed; Gboard shows no suggestion strip; the eye toggle keeps the keyboard, text and selection.

- Restoring native `leftElement` / `rightElement` / `clearable` on the native path.
- Defaulting autofill hints; `importantForAutofill` (not consumed by Compose).
