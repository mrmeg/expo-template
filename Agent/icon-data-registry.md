# Icons as app-owned glyph data: package renderers, `client/icons.json`, Lucide PNG tab icons; open `@mrmeg/expo-ui` 0.29.0

## Goal

`Icon` keeps its typed `name` API, but stops rendering `lucide-react-native` components. The package ships a snapshot of Lucide's glyph data plus two small renderers it owns (DOM `<svg>` on web and SSR, `react-native-svg` on native) and a CLI that compiles an app's `client/icons.json` name list into one plain-data module. The package's `IconName` shrinks to the 19 names its own components draw; an app adds any Lucide name with one word in `icons.json` and `bun run icons`, with no package release. The native tab bar draws PNGs rasterized from the same glyph data, so `@expo/vector-icons` Feather goes away. `lucide-react-native` leaves the peer list, so the root-import footgun (about 1.86 MB per platform per app when the tree-shaking flags are off, and 2.1 MB in the SSR bundle regardless) has nothing to resolve to. On web the eager `__common` chunk loses react-native-svg (9.5 KB br), the Lucide runtime (1.5 KB br) and the 145-glyph registry (9.5 KB br); each registered glyph then costs about 40 B br. Jest needs no icon mocks and no Lucide module mapping, because the glyphs are plain objects.

This is the package and template half of the decision recorded in the vault note (2026-10-11). The lint rule that bans Lucide and vector-icon imports in app code, and the per-consumer migrations, are separate follow-up specs.

## Decisions

- Builtins shrink to the 19 package names in this release, not in a later one. Consumers upgrading to 0.29.0 run `bunx expo-ui-icons init` once, add `registerIcons(appIcons)` to their root layout, and delete their Lucide Jest mapping; their `<Icon name>` call sites do not change. The CHANGELOG states this.
- Registration is an explicit module-scope call in the root layout module (`client/features/app/RootLayout.tsx`, next to `registerApiTokenGetter`), not a provider prop: it is deterministic on the server (the root layout module evaluates before any route renders; `inlineRequires` is off in Expo's default Metro config) and tests need no wrapper.
- No `custom` SVG entries, no codemod, no `strokeWidth` prop, no filled/heavier selected tab glyphs in this spec.
