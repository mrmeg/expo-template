# Fix README drift and add a version-drift guard

## Goal

Bring `README.md` in line with the actual stack (SDK 57 / RN 0.86, dual auth providers) and add a cheap check so version claims can't silently drift again. The README is the first thing humans and agents read when starting a project from this template; stale claims cost real debugging time.

## Context

Verified drift in `README.md` against `package.json` (expo `~57.0.8`, react-native `0.86.0`):

- Line 11: claims "Expo SDK 56 / React 19.2 / RN 0.85". (React 19.2 and RNW 0.21 are correct — only SDK and RN are stale.)
- Line 354: repeats "Expo SDK 56, React 19.2, React Native 0.85".
- Line 356: "Expo Router 56" — actual `expo-router` is `~57.0.8`.
- Line 365: "Jest 29 + jest-expo + RNTL 13" — actual `@testing-library/react-native` is `^14.0.1`.
- Line 123: generator comment says `client/screens/SettingsScreen.tsx`, but `scripts/generate.ts` writes `client/templates/<kebab>/` (Screen.tsx + demo.tsx + meta.ts) plus a route re-export. Fix the one line; the same stale `client/screens/` claim in `CONTRIBUTING.md` (55, 80, 88) and `docs/template-modernization-guide.md` is out of scope here.
- Lines 18, 157, 224, 358: describe auth as "AWS Amplify / Cognito" only. Actual selection lives in `client/features/auth/provider/index.ts` (`getAuthProvider()`): Clerk if `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` is set, Cognito if both `EXPO_PUBLIC_USER_POOL_ID` + `EXPO_PUBLIC_USER_POOL_CLIENT_ID` are set, Clerk wins when both are, `EXPO_PUBLIC_AUTH_PROVIDER` ("clerk" | "cognito") overrides, otherwise disabled. `AuthProviderGate.tsx` only mounts `ClerkProvider`. Server verification: `server/api/shared/clerkTokenVerifier.ts`. Line 224 is doubly wrong — `client/lib/api/authenticatedFetch.ts` calls provider-agnostic `getAuthClient()`, not Amplify.
- Already correct, do NOT "fix": `AGENTS.md` lines 35 and 41 (SDK 57 / RN 0.86; "Clerk or AWS Amplify/Cognito"). `packages/ui/LLM_USAGE.md:32` ("Expo 56–57 … RN 0.85–0.86") is an intentional supported-host range, not drift.
- `docs/` has no in-scope version drift: the only `docs/*.md` match for `SDK 56`/`0.85` is `docs/migration-guide.md:75`, which is the out-of-scope historical 55→56 content.
- `llms-full.txt`/`llms-examples.txt` are generated by `scripts/build-llms-full.mjs` from a fixed source list (`docs/template-modernization-guide.md`, `docs/migration-guide.md`, `packages/ui/LLM_USAGE.md`, `packages/media/README.md`, `docs/server-guide.md`, `docs/ssr-hydration.md`) plus directory walks. `README.md` is **not** a source — README-only edits leave `docs:llms:check` green.

## Work

1. Fix README lines 11, 354, 356, 365 and 123 per Context. Prefer wording like "Expo SDK 57 (exact pins in `package.json`)" where practical so the guard below has less surface.
2. Rewrite the auth mentions (18, 157, 224, 358) to describe the provider gate: Clerk or Cognito, selected by which env keys are present (`EXPO_PUBLIC_AUTH_PROVIDER` forces one), both optional and fail-closed to disabled.
3. Add `scripts/check-readme-versions.mjs`: asserts the expo major and react-native minor named in `README.md` match `package.json`. Wire it as `"docs:versions:check": "node scripts/check-readme-versions.mjs"` and add a step to `.github/workflows/ci.yml`'s `validate` job (after the "LLM docs freshness check" step). Also add it to `verify` if `local-verify-and-git-hooks.md` has already landed.
4. Run `bun run docs:llms` and commit regenerated outputs if changed (expected: no change, since README is not an llms source).
