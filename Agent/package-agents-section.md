# `expo-ui-agents`: managed `@mrmeg` package section in a consumer's AGENTS.md

## Goal
Agents in consumer apps should get the package rules without having to decide to read a doc. A new `@mrmeg/expo-ui` bin, `expo-ui-agents`, writes a marked, versioned section into the consumer's root `AGENTS.md`. The section inlines the compressed index of every installed `@mrmeg` package, plus the version-matched doc paths in `node_modules`. `--check` lets CI catch drift after a package bump.

Why inline rather than point: Vercel's eval (https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals) found a compressed docs index in AGENTS.md passed 100%. A skill the agent had to choose to use scored 53%, the same as no docs, and was never invoked in 56% of cases. Convex ships the same pattern as `npx convex ai-files` (a managed section in AGENTS.md/CLAUDE.md, with a `status` check).

## Context
- Each package already ships a compact index in its tarball: `packages/ui/llms.txt` (2.4 KB), `packages/media/llms.txt` (1.7 KB), `packages/purchases/llms.txt` (1.9 KB). `ui` also ships `LLM_USAGE.md` and `llms-full.md`.
- The lint plugin (`packages/lint`, bin `expo-ui-lint`, `--changed`/`--base`/`--doctor`) is not on npm yet. It ships no `llms.txt`.
- `ui` already has one bin, `packages/ui/bin/expo-ui-icons.mjs`. It is Node ≥ 20 with no dependencies, uses a `CliError`/usage pattern, and is tested in `scripts/__tests__/iconsCli.test.ts` and exercised in the ui consumer-smoke fixture (`scripts/check-package-consumer.mjs`, ui `steps`).
- Today 8 consumer repos hand-write their own pointers to these docs, inconsistently: fieldnest says "read LLM_USAGE.md before any UI"; downrangedays and simplesell say nothing.
- A consumer `AGENTS.md` may also hold a `## Agent Workflow` section (marker `<!-- agent-framework:vN -->`, owned by agent-framework's `init.sh`) and a `<!-- convex-ai-start -->…<!-- convex-ai-end -->` block (owned by `npx convex ai-files`). Neither may be touched.

## Work
1. Add `packages/ui/bin/expo-ui-agents.mjs` and register it in `packages/ui/package.json` `bin`. Follow `expo-ui-icons.mjs` conventions (no dependencies, usage text, exit codes).
   - `expo-ui-agents` writes or refreshes the section. `--check` exits 1 when the section is missing or stale and writes nothing. `--file <path>` defaults to `AGENTS.md` in the cwd and creates it if absent.
   - It detects packages from the consumer's `package.json` (`dependencies` + `devDependencies`): `@mrmeg/expo-ui`, `@mrmeg/expo-media`, `@mrmeg/expo-purchases`, `@mrmeg/eslint-plugin-expo-ui`. It resolves each one's installed `package.json` version and `llms.txt` from `node_modules`. Skip any that are listed but not installed, and warn.
   - Section shape, between `<!-- @mrmeg/packages:start -->` and `<!-- @mrmeg/packages:end -->`, under a `## @mrmeg packages` heading:
     - a one-line "generated by `expo-ui-agents`; edit the packages, not this block" note;
     - `Installed:` with names and versions;
     - per package, a `###` heading and the body of its `llms.txt` (drop its H1);
     - a `Docs:` line listing only files that exist in that installed version (e.g. `LLM_USAGE.md`, `llms-full.md`, `docs/components/index.md` once that spec lands).
     - When the lint plugin is installed, a closing line: after UI edits run `bunx expo-ui-lint --changed` (`--base main` where there is no `dev`).
   - Placement: replace an existing marked block in place. Otherwise insert it immediately before `## Agent Workflow` if present, else append it. Bytes outside the markers stay byte-identical, including the Convex block and the workflow section.
   - The output is deterministic (stable package order), so `--check` is a plain comparison.
2. Keep the inlined content small. Add a test that fails when any package's `llms.txt` exceeds 3 KB, or the generated section for all three exceeds 8 KB.
3. Tests in `scripts/__tests__/agentsCli.test.ts`, modeled on `iconsCli.test.ts`:
   - inserts before `## Agent Workflow`;
   - appends when there is no workflow section;
   - replaces in place and is idempotent;
   - leaves Convex and workflow blocks untouched;
   - lists only installed packages;
   - `--check` returns 0 when fresh, 1 when missing or stale;
   - creates `AGENTS.md` when absent.
4. Consumer smoke: in the ui fixture (`scripts/check-package-consumer.mjs`), add steps that run `bun x expo-ui-agents`, then `bun x expo-ui-agents --check` (exit 0), and assert the written section names the installed version. Add `bin/expo-ui-agents.mjs` to ui `requiredDocs`.
5. Docs:
   - `packages/ui/README.md`: a short "Agent setup" section with the command and a CI `--check` line.
   - `packages/ui/LLM_USAGE.md` top and `packages/ui/llms.txt`: mention the bin.
   - `packages/ui/CHANGELOG.md` entry.
   - Bump `packages/ui` to the next minor (a new bin needs a release).
   - Run `bun run docs:llms` if any source doc of `llms-full.txt` changed.

## Out of scope
- Running the bin in the 8 consumer repos and deleting their hand-written pointers: per-app follow-up after publish.
- A standalone agent skill or an MCP server.
- Using this in the template repo itself, whose `AGENTS.md` already indexes the workspace docs.

## Validation
- `bun run test:ci -- scripts/__tests__/agentsCli.test.ts`
- `bun run pkg ui consumer-smoke`
- `bun run verify`
- Manual: in a scratch copy of a consumer with a Convex block and a workflow section (e.g. a temp clone of `~/Development/fieldnest`), run the packed bin. Check that `git diff` touches only the marked block and that `--check` exits 0 afterwards.
